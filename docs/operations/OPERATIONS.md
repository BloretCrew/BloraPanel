# 运行、升级与恢复

本手册对应当前源码和命令行入口。初始化与双节点本机验收见[项目说明](../../README.md)；完整实现和验证边界见[验收矩阵](../acceptance/ACCEPTANCE_MATRIX.md)。本文没有执行公开部署、系统服务安装或生产节点变更。

生产环境的三个组件分别启动方式见 [English README](../../README.md#production-startup) / [中文 README](../../README.zh-CN.md#生产环境启动)：包括真实 Master 初始化/常驻、Daemon 登记、Master 托管或独立前端、Linux systemd 与 Windows 命令。可编辑示例为 [Master unit](examples/blora-master.service)、[Daemon unit](examples/blora-daemon.service)、[Master JSON](examples/master.json)、[Daemon JSON](examples/daemon.json)和 [Nginx 配置](examples/nginx.conf)。示例需匹配目标账号、证书、目录和节点能力；示例文档本身不代表已执行生产部署。

Linux有限系统管理只接受明确的单元名称：服务操作使用完整`.service`名称（如`sshd.service`），计划任务启用/禁用使用`.timer`名称（如`backup.timer`）。不接受文件路径，不通过服务接口操作`.target`、`.mount`或`.socket`。Windows继续使用其服务名和任务路径合同。

## 文件与运行身份

将发行文件、私有状态和被管理资源分开保存：

- 发行文件：`blora-master`、`blora-daemon`、配套的完整`web/dist`；Windows为对应`.exe`。同一版本的前后端一起更新，保留上一套完整发行文件。
- Master状态：配置文件 `stateDir` 下的数据库（可选直接 HTTPS 模式另有证书/私钥）；另保留 `master.json`、配置指定的扩展安装目录、注册源及可信公钥。
- Daemon状态：配置中的`stateDir`，包含节点私钥身份、执行记录、归档、容器/Compose恢复记录及文件任务状态。每节点单独使用一个目录和身份。
- 资源数据：实例授权目录、Docker卷/绑定目录、备份目标。资源数据不因备份Master数据库而自动得到保护。

状态及身份目录只授予运行账号和获准管理员访问；复制备份时保留这些权限。不要把`.local/fixture-*`中的测试账号、票据或证书用作生产初始化材料。不要让两个Daemon同时使用同一身份目录。

Linux原生实例需要管理员预先委派可写的cgroup；`allowPGIDFallback`仅供信任工作负载的管理员显式启用。普通用户实例走受限容器路径。宿主Shell和系统管理权限独立于实例查看/控制权限。

## 启动与健康检查

Master 默认读取可执行文件同目录的 `master.json`，Daemon 默认读取同目录的 `daemon.json`；相对路径和未填写的数据路径按可执行文件目录解析，不受当前工作目录影响。Master 数据默认 `state/master`，Daemon 默认 `state/daemon`，前端默认 `web/dist`。参考[生产 Master 配置](examples/master.json)、[生产 Daemon 配置](examples/daemon.json)或根目录[Master 便携模板](../../master.example.json) / [Daemon 便携模板](../../daemon.example.json)。修改配置后重启生效。

在 Master 私有 `passwordFile` 中写入初始密码后，首次启动自动初始化并常驻；后续复用已有账号。Daemon 私有配置填入一次性票据路径，上线后复用自身身份。均无须启动参数：

```sh
./blora-master
./blora-daemon
```

默认后端 `http://127.0.0.1:37861`，不绑定外部域名，不生成或要求后端 SSL 证书。Nginx 终止 HTTPS、覆盖转发头，将 API/WebSocket 代理到本机 HTTP。真正回环连接可使用 HTTP/WS；外部浏览器和远程 Daemon 通过 Nginx HTTPS/WSS，远程 HTTP 管理连接会拒绝。

默认 `verifyProxyIPs:false` 不要求代理 IP 白名单，读取转发原始主机/协议/IP；请求头无法证明 Nginx 身份，后端保持只监听本机，入口必须覆盖客户端传入的头。开启 `verifyProxyIPs:true` 后，必须在 `trustedProxies` 配置非空 IP/CIDR 列表，非可信来源的头被忽略。严格模式按 XFF 右到左停止于首个不可信跳点，默认全信任模式采用转发链最左端地址，因此单层 Nginx 示例直接覆盖 XFF 为 `$remote_addr`。错误/歧义头仍拒绝，原始来源用于浏览器 API/WS 校验及 Cookie 安全属性，真实 IP 用于登录限流。

```sh
curl --fail http://127.0.0.1:37861/healthz
```

外部入口用自己的 Nginx HTTPS 地址检查；`/healthz` 只验证 Master 数据库，不等于节点可运行。关闭面板窗口不会停止后端资源。详细步骤见 [README](../../README.md#production-startup)。本次默认值晚于 beta.1，需构建当前源码，不改变旧版本附件。程序仍保留可选直接 HTTPS 配置及旧 fixture 参数兼容。

## 在线更新与维护升级

当前源码支持从预构建 Release 下载并切换管理子进程，入口为管理员设置和节点管理。默认来源、镜像、兼容限制见 [README 在线更新](../../README.zh-CN.md#在线更新)。此方式保留运行实例，不保证管理连接、交互终端或上传连接连续；不存在源码编译步骤。

相同存储迁移指纹和兼容协议的更新才允许自动交接/候选失败回退；存储或核心架构不兼容时，继续使用下面的一致性备份和停机维护流程。发布者必须提供与编译产物一致的 `CORE-UPDATE.json`、四份组件归档和 `SHA256SUMS`；`make package` 生成这些材料。旧 beta 包不支持新在线更新合同。

## 升级前的一致性备份

当前全平台状态备份流程采用停机窗口。平台内“实例备份”保护选定资源内容；它不是Master、全部节点身份及管理数据库的联合快照。

1. 停止新增管理操作，停用将触发新工作的计划，等待已接受任务结束；对等待/失联/结果不明的任务先完成对账，不把它们当作已停止。
2. 显式停止受影响实例并确认实际退出；结束PTY。记录节点、实例、最后运行ID及任务结果。Daemon退出本身不等于实例停止，独立日志辅助进程也可能继续写文件。
3. 停止Daemon和Master，确认本次要备份的目录不再被写入。若不能确认某节点静止，仅能记录该节点未形成一致备份，不能宣称联合恢复点完整。
4. 用受控备份工具复制整个Master状态目录、每个Daemon状态目录、配置、CA/私钥、外置扩展目录和对应资源备份。保留SQLite的数据库及伴随WAL文件；不要在服务仍写入时只复制`.db`文件。
5. 保存当前二进制、前端文件、配置与备份清单及校验和。身份文件和证书密钥的副本保持私有，不写入公开日志、仓库或验收截图。

新程序启动时逐个事务应用已知迁移。迁移记录必须是该程序支持的连续前缀；未知版本或记录缺口会拒绝启动，保留数据供兼容版本处理。禁止通过删除`schema_migrations`记录绕过该保护。

## 更新与核验

在独立发行目录准备新二进制与完整前端，保留原状态路径和节点身份。先启动Master检查迁移与健康状态，再逐个启动Daemon，确认身份未改变、连接代次更新、旧执行记录完成对账。最后使用获准测试资源验证读取、文件保存、任务和终端恢复，再恢复计划触发。

Daemon重新连接不自动重发浏览器输入。当前不承诺Daemon退出后所有PTY继续存活；界面必须呈现实际关闭/中断状态，不能用新Shell冒充旧会话。Compose恢复失败时保留`containers/cli-runs/`及原任务诊断，先核对所有权和实际资源，不能删除记录强行跳过。

## 回退

回退前再次停止新版本产生的工作并确认资源退出。使用与数据库迁移版本兼容的二进制；若需要恢复旧备份，应恢复同一静止恢复点的Master、相关节点状态及资源数据。不能把旧运行记录覆盖到仍存活的新运行上，也不能混用不同时间点的Master任务记录和Daemon执行记录。

保留失败版本的状态副本和日志，先在独立目录验证备份可读取。恢复身份到替代节点前确认原节点不会同时上线。恢复后重新核对授权、任务、实例实际状态和计划触发，再开放操作。

源码仓库提供针对 Linux 发行包的独立演练入口（在仓库根目录运行）：`python3 scripts/package-smoke.py dist/releases/<版本> --state-restore`。它在随机私有目录启动解包后的 Master 和两个 Daemon，停止所属进程后复制状态及配置，制造后续变更，再恢复快照并核对 TLS、节点身份、用户授权、任务回执与资源正文。可追加 `--upgrade-from dist/releases/<兼容旧版本>`，先由旧包创建状态，再停机并由当前包打开同一状态验证升级；追加 `--rollback-release dist/releases/<兼容旧版本>` 则由旧包打开最终恢复点。带回退参数的运行不替代当前包自身恢复验证；这不证明任意数据库版本都可降级。演练不接触现有部署，不能与崩溃测试参数混用；结果以实际命令退出和验收报告为准。

## 常见诊断

| 现象 | 核对内容 |
| --- | --- |
| 节点失联、任务等待 | Nginx HTTPS/来源、本机后端连接、节点身份和管理连接；实例业务进程可能仍在运行 |
| 生命周期结果不明 | 原runId、退出证明和持久执行记录；未确认旧运行退出前不要重复启动 |
| 工作现场未受保护 | 浏览器存储失败或配额；保留当前内容并使用导出入口，不能清空恢复记录后声称成功 |
| 终端归档有缺口 | 本地检查点早于归档保留范围；保留屏幕并呈现实际边界，不能重发历史命令补现场 |
| 大文件传输缓慢 | 实际RTT、限流、磁盘同步延迟和任务已确认偏移；文件已发送不等于目标已验证 |
| 未知数据库迁移 | 使用匹配版本或一致备份；不要删版本记录或把旧程序强行接入新数据库 |
| Compose遗留CLI无法恢复 | 保留所有权记录，核对本机进程检查权限；CLI退出与远程Engine资源结果分别对账 |

终端输出增量受64KiB/128条上限约束，默认PTY归档16MiB；软件WebGL环境自动选用默认渲染器。跨节点传输的分块校验索引最多64条/8MiB每文件服务，最终仍核验源和目的内容。具体测量、失败历史和可复现命令见[性能证据](../acceptance/reports/performance-real-2026-09-13.md)及[传输索引证据](../acceptance/reports/transfer-proof-2026-09-13.md)。

Windows真机、真实物理掉电/空间耗尽、危险主机变更和长期网络组合的验证状态单列在验收矩阵中；本文步骤本身不是这些场景已通过的证明。
