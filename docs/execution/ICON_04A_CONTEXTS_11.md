## 采集与核对

- [采集脚本](../../web/.local/capture-04a-contexts.mjs)：在 `web` 目录执行 `npm run dev -- --port 5173 --strictPort`，然后执行 `node .local/capture-04a-contexts.mjs`。
- 浏览器 Chromium，禁用 WebGL，2 倍像素采集；常规视口 1600×1000，另含 1366×768、1024×768。
- 每次截图检查全部应用图标为 `h04-pastel-silver`，并逐一解码 288×288 资产；14 张选中资产正常加载。
- 24 张截图采集完成，页面异常 0，API 写请求 0。图库 27 张图片（24 张截图与 3 张页头图标）均解码成功，深色、小屏、细节、全部四个筛选分别为 3/3/4/24 张。
- 首次采集结束时发现验证脚本把 Vite 默认图标 URL 模块请求也算作实际图片，导致计数 28 而非 14；改为分别记录模块与选中目录资产，同时保留所有 DOM 图标检查。完整重跑通过。

## 数据与现状

所有应用均为实际 Vue 组件；文件内容由 Monaco 渲染。截图数据来自脚本内只读演示样本，所有 API 请求均被拦截；非 GET 请求禁止发送。终端由实际 xterm 及项目 Protobuf 协议渲染，传输来自本地只读样本，未创建 PTY 或运行截图中的示例命令。因此这些图片仅是视觉证据，不计入后端、节点、终端真实性验收。

深色场景如实展示当前深色主题：主题仍使用浅色壁纸，桌面图标文字对比度不足，后续需统一调整。此轮未借截图任务改变用户已选的浅色风格。

没有修改生产源码，本轮不重复产品构建。临时 Vite 与采集浏览器均已关闭。下一动作：依据用户对这些 04A 实景截图的反馈继续收敛，默认图标仍未切换。
