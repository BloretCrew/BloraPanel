# Blora Panel v0.1.0-beta.1

**Prerelease for initial hands-on evaluation.** The project owner has not yet
personally tested the application. This build has automated and agent-run
validation; stable-release readiness is not claimed.

## Included

- A Material Design 3 desktop with multiple windows/tabs, light/dark appearance,
  six palettes and independently selectable translucent materials.
- Go Master and Daemon services for nodes, instances, files, Monaco editing,
  PTY terminals, persistent tasks, monitoring, Docker/Compose and backup schedules.
- Resource permissions, immediate workspace recovery, controlled extension
  installation and a standalone SDK with reference applications.
- Bounded mixed-load latency improvements and the final Chromium rounded-window
  and terminal-toolbar rendering repairs.
- Locked dependency security patches: DOMPurify 3.4.16 and source-map-js 1.2.2.
  The original dependency versions were reviewed before packaging; the beta's
  final npm audit reports zero findings. DOMPurify's upstream fix is documented
  in its [security advisory](https://github.com/cure53/DOMPurify/security/advisories/GHSA-p98j-92pf-mc4p).

## Downloads and installation

Choose the Master and Daemon archives for **Linux amd64** or **Windows amd64**.
The Master archive already includes the frontend. The standalone Web archive is
for separate frontend distribution; the SDK archive is for extension developers.
The source archive contains the exact committed build inputs.

Verify `SHA256SUMS`, extract each component into its own directory, and read
`START.txt` and `docs/operations/OPERATIONS.md`. Initialize the Master once using
`--init --password-file`; there is no shared default password. Use private state
directories and matching HTTPS origins/certificates. Windows binaries are console
applications, not native Windows service executables.

## Validation and limits

The source closeout includes 123 passing frontend units, backend race checks,
Linux/Windows compilation and all 51 real functional scenarios across a complete
run and independent follow-ups. Earlier complete-run failures remain visible in
the acceptance reports; this does not claim a single completely green run.
Packaged startup, SDK build/signing, stopped-state restore and compatible
development-package upgrade/rollback results are reported with this release.

- The E08 extreme eight-window workload measured Chromium 38.8ms, Firefox 66ms
  and WebKit 89–132ms (last repetition 95ms), on the recorded pre-release source.
  These are source-specific measurements, not a stable 50ms or 100ms guarantee.
- The 200-line native bulk-input scenario still takes about 10–11 seconds.
- Previous Windows Job/ConPTY and 14-check device results cover their recorded
  commits. The new Windows archives are built and integrity-checked; they have
  not been rerun on a Windows device as part of this release.
- Host-management support follows declared platform capabilities. Windows
  firewall changes/rollback are not supported. Physical Safari and every device,
  network and physical-failure combination are not certified.
- Rollback is limited to verified compatible schemas and a consistent stopped
  snapshot; arbitrary schema downgrades are not supported.
