## 本轮修复过的真实问题

1. 原 Monaco 用例聚焦了 Chromium 新版 EditContext 的隐藏 readonly IME textarea，实际没有输入正文。改为定位可访问的“文件正文编辑器”，保留原测试场景与全部断言。
2. 复制工作区保留 view/window ID，Vue 原来复用旧组件，导致 Monaco 仍写入来源工作区。窗口渲染 key 增加工作区身份，Editor 捕获所属 RecoveryService；保存响应也固定所属服务、draftId 和资源，避免切换后写错现场。
3. 一个原生 Monaco 更新可能发出多个内容事件。旧日志恢复将每条增量独立建撤销边界，多光标一次输入刷新后只能撤销末字符。现在同步持久化同一更新的分组标识，恢复时用公开模型编辑接口重建分组，并按正文正反向增量核对真实撤销位置。扩展用例最终通过，验证刷新前后真实的同一步 undo/redo。
4. 同页重新登录原先会再次争用自己持有的 Web Lock；复制浏览器标签分配新 ID 后没有持有新锁。现在页内身份复用，复制分支取得独立锁。
5. 关闭、最小化、标签移入后台窗口后，原先活动窗口或层级可能失效；已修复活动窗口回退、目标窗口置前、显式重开最近标签并保留身份。
6. 不兼容恢复记录读取失败后，后续提交原来可能覆盖旧快照。现在保留原记录供导出，并禁止对失败的恢复记录写回。
7. 真实登出追加用例发现清理后硬刷新与下一次登录导航竞争。已去掉不必要的硬刷新，清理期间暂停登录；新增真实账号切换用例已通过。
