# B06 安全文件库验证记录

日期：2026-09-09。范围：`internal/filesystem`；本记录不是整个 F07/F08 或 A01/A02/A07/A12 的全链路通过声明。

## 实现

- Daemon 选定根目录的 `os.OpenRoot` 句柄；API 只接受 slash 相对路径。私有检查点目录必须位于服务根外。所有 `.blora-*` 名称保留给暂存/回收；它们不会通过文件 API 暴露。
- 拒绝绝对路径、`..`、Windows 盘符/UNC/ADS/设备名、尾随空格与点、符号链接和特殊文件。Unix 读取使用 nonblock 打开后复核文件类型，避免 FIFO 替换竞态挂起。
- 分页目录与目录版本、UTF-8/BOM/LF/CRLF 文本读取、大小/二进制拒绝。保存必须携带版本，平台内路径及祖先操作串行，临时文件 sync 后替换并同步目录。普通创建使用 `MissingVersion`。
- 有界递归复制、重命名/移动、回收删除、恢复和显式过期回收。复制保留基本权限和修改时间。跨文件系统移动先复制、核验来源，再将源移入本盘回收对象；不能完成源阶段时保留目标与源并返回真实阶段。跨盘回收对象、未结束上传会阻止其祖先移动，避免丢失检查点路径。
- ZIP 压缩与解压；中央目录在调用标准解码器之前检查规模，拒绝 zip-slip、特殊文件、重复及大小写碰撞、CRC 错误、超大展开比例和隐式目录数量炸弹。目标合并按文件版本显式覆盖，部分提交后取消返回 `Completed`。
- 上传绑定 ID、用户、目标、总长、总 hash、基线版本、来源名称/时间/指纹及跨节点来源引用。每个 64 KiB 顺序分片先同步节点文件再原子同步检查点。重新打开 Service 后从节点确认 offset 续传；重复片必须匹配已确认字节。提交重新校验总长/hash/基线；提交中断与取消中断有持久阶段核对。
- `ReadChunk` 返回 source version、offset、total、chunk hash、bytes；每片前后重新计算全文件版本，拒绝来源变化。Master 必须在独立批量通道转发并再次校验。

默认限制：单文件 1 GiB、文本 4 MiB、单次树操作/活跃上传保留量 4 GiB、目录/树 100,000 项、并发文件调用 4、活跃上传 16、分片 64 KiB、回收区 4 GiB/30 天。ZIP 单卷标准格式至多 60,000 条目录记录，中央索引至多 32 MiB，展开比大于 1000 且展开大于 1 MiB 时拒绝；ZIP64 和自解压格式明确返回不支持。

## 已运行

环境：Fedora Linux x86_64，Go 1.25.9；真实 `t.TempDir` 文件、符号链接与 FIFO；没有连接生产节点。命令均使用：

```sh
export GOCACHE=/tmp/blora-go-build GOMODCACHE=/tmp/blora-go-mod GOPATH=/tmp/blora-go GOFLAGS=-buildvcs=false
go test -race ./internal/filesystem
go vet ./internal/filesystem
GOOS=windows GOARCH=amd64 go test -c -o /tmp/blora-filesystem-windows.test.exe ./internal/filesystem
```

最终结果：race 测试退出 0（1.285s）；vet 退出 0；Windows amd64 交叉编译退出 0。此前覆盖率测量为 72.4%，其后又增加祖先移动保护和 ZIP 隐式目录/目录链接用例；该旧数字不表示最终覆盖率。

测试覆盖并发同基线保存仅一个成功、外部写入冲突、UTF-8/二进制/体积边界、目录版本翻页、递归复制移动回收恢复、回收配额与只清理自身对象、ZIP 恶意路径/链接/CRC/覆盖/炸弹、真实已提交子项后取消、重开句柄恢复上传、未确认尾部处理、源指纹改变、重复片改变、总hash冲突、目标改变、取消隔离、提交/取消的崩溃窗口核对、空文件、上传总量和读分片来源变化。Linux 用例还持续切换普通目录与指向根外的链接，检查读写未逃逸。

## 未验证和边界

- Windows 真机、NTFS 原子替换/权限/时间行为未验证。Windows 对文件执行 `Sync`；标准 `os.Root` 的只读目录句柄无法执行 `FlushFileBuffers`，不声称 Windows 断电后的目录项持久性。提供实际测试程序而非成功桩。
- 当前环境未运行真实跨文件系统移动/回收或磁盘写满故障；相应代码返回实际系统错误，不把缺环境计作通过。
- 本库没有用户鉴权、任务索引、网络中继或浏览器恢复；这些由 Master/Daemon 集成负责。每个实际根须复用一个 Service，不能给每个视图各建路径锁。私有 StateDir 需要节点 ACL/容器挂载隔离；文件 API 的根限制不替代任意进程执行隔离。
- `os.Root` 不阻止管理员预先放入根内的挂载点或普通硬链接。符号链接越界的安全边界由目录句柄保证，不能将路径字符串检查当作底层保护。
- 外部程序不参与平台路径锁。与任意持续写入者之间不承诺通用原子比较交换；数据库/运行中存档仍需停写或应用协议。每片全文件重算版本有明确 I/O 成本，大文件吞吐仍需集成测量。
- 每次树操作的容量上限不是整台主机的文件系统配额；已经提交的用户数据需结合节点/实例磁盘配额。回收保留期由 `PurgeExpired` 入口执行，终结传输/回收清单和过期检查点临时文件由 `PruneRecords` 清理；调用方应接维护调度并保留任务结果，活跃上传不会被该清理方法删除。

API 依据：[Go os.Root](https://pkg.go.dev/os@go1.25.9#Root) 与 [Go 目录句柄安全说明](https://go.dev/blog/osroot)，另核对了当前安装的 Go 1.25.9 标准库实现。上述资料的能力边界未作为本地测试通过的替代品。
