# 真实目标空间不足验收

Linux 内核私有 user/mount namespace，真实 HTTPS Master + 两个 Daemon。测试自身用 `unshare --user --map-root-user --mount` 启动子进程，核对命名空间与父进程不同，设为私有挂载，再将容量1MiB的tmpfs挂到仅属于测试的目标目录。未填满宿主磁盘、未改宿主挂载。无环境能力时不得把跳过记为通过。

## A12 跨节点移动

代码：`internal/master/transfers_enospc_linux_test.go`。

```sh
GOCACHE=/tmp/blora-go-full-final54 GOMODCACHE=/tmp/blora-go-mod GOPATH=/tmp/blora-go \
GOFLAGS=-buildvcs=false BLORA_TEST_ENOSPC=1 \
go test -race ./internal/master -run '^TestTransferTargetENOSPCKeepsMoveSource$' -count=1 -v
```

结果：通过，退出0，4.371s（私有子场景2.32s）。目标真实返回 `no space left on device`；任务FAILED且清理完成，源二进制内容逐字节保持，目标文件未发布，原有目标文件保持；`.blora-files/work`、`uploads`、`trash`均为空。首轮仅清理断言误将服务标准空目录视为残留，修正为核对目录内容后通过。测试退出卸载私有tmpfs并关闭所属服务。

该证据补齐A12的Linux真实空间不足子场景；tmpfs不等同于ext4/NTFS物理断电耐久性，Windows与远程文件系统仍分别未验证。新增验收测试晚于rc2打包，不在该归档中；本次未修改传输生产代码。

## E03 备份仓库空间不足

`internal/master/backups_enospc_linux_test.go` 的 `TestBackupRepositoryENOSPCDoesNotPublishArchive` 在独立1MiB仓库创建不压缩归档，实际写入触发ENOSPC。任务FAILED且错误明确，未发布快照、未留下pending或objects文件，源内容不变，回执不声称成功或未知清理。

沿用上述环境运行 `go test -race ./internal/master -run '^Test(TransferTargetENOSPCKeepsMoveSource|BackupRepositoryENOSPCDoesNotPublishArchive)$' -count=1 -v`：2/2通过，退出0，6.505s。共享隔离子进程入口已改为按测试名启动，仍检查父/子挂载命名空间区别。

## E03 恢复目标空间不足

`TestBackupRestoreENOSPCKeepsExistingTarget` 先从1MiB私有目标中的768KiB文件生成有效备份，再将目标替换为较小的当前正文、写入512KiB同目录文件。明确确认覆盖后，恢复暂存真实触发ENOSPC；任务FAILED，当前正文与其他文件逐字节保留，原快照仍可列出，work/uploads/trash暂存目录为空。

同环境 `go test -race ./internal/master -run '^TestBackupRestoreENOSPCKeepsExistingTarget$' -count=1 -v`：退出0，3.678s（子场景1.63s）。三个场景均执行真实内核空间不足而非错误注入，私有挂载与测试服务退出清理。物理掉电、Windows及应用一致性语义仍未由这些场景证明。
