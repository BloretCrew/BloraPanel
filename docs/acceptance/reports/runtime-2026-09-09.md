# B04 运行适配库实施与验证

时间：2026-09-09 05:27 UTC。范围仅为 `internal/runtime`；不代表 Daemon/Master/UI 全链路、A03/A04/A05/A10 整项已通过。

## 实现

- `runtime.go`：按 runId 的独占启动声明、原子记录与文件同步、恢复核对、阶段持久化回调、有界停止/升级/退出确认、清理前保存退出证据。任务去重、不同 runId 对同一实例的串行执行和授权由 Daemon 负责。
- `native_linux.go`：管理员指定的受委派 cgroup v2 子树，每次运行独立目录；通过 Go `UseCgroupFD` / `CLONE_INTO_CGROUP` 在 exec 前加入 cgroup；memory/cpu/pids 限制；`cgroup.kill` 与 `cgroup.events populated` 确认；恢复校验 boot ID 与 cgroup inode。不会自行写根 cgroup。Go 1.25.9 本机源码 `/usr/lib/golang/src/syscall/exec_linux.go:313` 已核实真实 API。
- 无 cgroup 时必须显式设置 `AllowPGIDFallback`。进程组只面向可信原生进程，不作为不可信租户隔离；boot ID、PID start ticks 与继承的运行标识用于核对，pidfd 避免向复用 PID 发信号。缺少资源控制时拒绝限额配置。主动脱离组的后代不在这一降级保证内。[Linux cgroup v2 文档](https://docs.kernel.org/admin-guide/cgroup-v2.html)
- `native_windows.go`：真实 Job Object、有限继承句柄列表、禁用 breakaway、内存/进程数/CPU 限制。`PROC_THREAD_ATTRIBUTE_JOB_LIST` 在创建时原子加入 Job，同时 `CREATE_SUSPENDED`；核对成员身份、持久化 PID 和创建时间后才 `ResumeThread`。使用 Job ActiveProcesses 和成员列表确认整次退出。Daemon 丢失最后 Job 句柄时按 `KILL_ON_JOB_CLOSE` 收敛，恢复真实核对，不能宣称 Daemon 升级后原生进程永久存活。要求 Windows 10+ 相应创建属性；缺少能力直接报错。[Microsoft 创建属性](https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-updateprocthreadattribute)、[Job 生命周期](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects)
- `docker.go`：直接 Engine API 1.45；先验证 Engine 最小/最大版本与 Linux OSType。仅允许配置的本地 Unix socket 或验证 TLS 的 HTTPS 管理端点；普通实例不能提交 HostConfig。非 root 用户、只读根、drop ALL capabilities、no-new-privileges、私有 PID/IPC/cgroup namespace、资源限制、有界 Engine 日志、唯一受控 `/workspace` 挂载、有限 `/tmp`。无特权模式、socket、设备、host namespace 或任意宿主机挂载参数。每次信号和删除重验完整容器 ID 与所有权标签，删除默认保留数据。模板输入用真实 Engine attach 升级连接；日志以 Engine 流暴露。[Engine API](https://docs.docker.com/reference/api/engine/version/v1.45/)、[Engine 安全边界](https://docs.docker.com/engine/security/)

依赖使用主工程已锁定的 `golang.org/x/sys v0.40.0`；未修改根 go.mod/go.sum。

## 接口与集成约束

```go
manager, err := runtime.New(runtime.Options{
    StateRoot: "/configured/daemon/runs",
    InstanceRoot: "/configured/daemon/instances",
    AllowPGIDFallback: true, // 仅管理员明确启用的可信模式
})
record, err := manager.Start(ctx, runID, instanceID, config, runtime.IO{
    Stdin: childPipeRead, Input: parentPipeWrite,
    Stdout: outputFile, Stderr: outputFile,
})
record, observation, err := manager.Recover(ctx, runID)
observation, err = manager.Stop(ctx, record, runtime.Policy(config), persistPhase)
```

- `persistPhase` 为 `func(string) error`，返回错误则不执行下一阶段的副作用；阶段为 STOPPING/KILLING/VERIFYING_EXIT。
- Daemon 必须先持久化选定的新 runId，再调用 Start。Start 返回错误仍可能已经执行过启动，例如运行身份最终保存失败、Engine 丢响应；应 Recover 原 runId，不能重发启动。
- 输出使用真实文件描述符，进程 Wait 不依赖 io.Copy 或输出 EOF。PTY 和有界归档由 B05 集成；本库不把主 PID 退出或输出管道关闭当作整次运行退出。
- `IO.Stdin` 是子进程读端；`IO.Input` 是父进程写端。`WriteInput` 上限 64 KiB，单次写有截止时间；部分写/错误不能自动重试。原生输入通道不能在 Daemon 崩溃后凭记录重新挂载，恢复时明确报能力缺失。Windows 服务模式的控制事件及管道输入仍需真机验证；ConPTY 归其他模块。
- 容器工作目录是 `/workspace` 或其子目录；宿主来源只能是 `InstanceRoot/instanceID`。InstanceRoot 的父目录由管理员控制，容器 Engine 必须正确映射该宿主目录。新建目录需要设置非 root UID/GID 的权限；已有目录不会擅自改 owner。镜像必须已存在，拉取由上层镜像任务执行。
- `Cleanup` 只删除本次已确认退出的归属单元/容器，保留运行审计记录和实例数据；可重复调用。进程限额、PGID 弱约束和未知观察均不能映射为伪成功。
