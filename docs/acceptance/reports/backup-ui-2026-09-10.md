# 备份与定时任务界面增量（2026-09-10）

默认桌面现在注册 `blora.backups` 应用，并从实例管理窗口提供“打开备份与计划”入口。应用使用真实 Master API：创建前读取节点返回的源版本，提交后只显示服务端任务状态；恢复先生成不可变恢复计划，列出现有目标，最终请求使用计划 hash 作为显式覆盖确认；保留策略和定时任务也沿用任务、修订号、幂等请求键和服务端再次授权。

一致性策略选择器保留 `files/save/pause/stop/hooks` 的合同。未在 Daemon 配置 `backupHookCommands` 时，后四项由后端返回 capability unavailable，界面明确说明原因；配置固定 argv 后由 Daemon 的持久 HookRunner 执行，不把普通文件打包伪装成应用一致性快照。定时备份使用 `files` 策略，并提供时区、错过执行和重叠策略；节点离线或权限撤销仍由 Master 调度器处理。

新增浏览器场景：

```text
cd web
npm run test:e2e -- --workers=1 --trace=off --grep 'backup UI' --reporter=line
```

结果：1/1 通过（5.1s，允许本地 Vite/Chromium 监听）。场景断言了版本读取、备份任务提交、恢复计划与 `overwritePlanHash`、定时任务提交四条请求；前端 `npm run check && npm test -- --run` 为 28/28，生产构建退出 0。

这份增量证据覆盖界面到 API 的请求绑定，不替代真实节点上的 ENOSPC、掉电、长时调度和产品 HookRunner 场景；这些仍按[备份与调度模块](backup-scheduler-library.md)记录。
