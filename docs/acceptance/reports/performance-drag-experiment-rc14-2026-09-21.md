# 拖窗性能优化尝试（2026-09-21）

E08 诊断显示拖动窗口时同时有输入排队和渲染耗时，因此尝试在 `requestAnimationFrame` 内直接写目标窗口的 DOM 几何样式，避免每帧更新 Vue 响应式状态；松手后仍通过既有 `desktop.geometry` 提交完整几何。该方案不改样式值或外观。

| 运行 | 场景 | 结果 |
| --- | --- | --- |
| 首次试改 | 真实桌面几何 13 项 + 独立混合性能项；每帧同时写 transform/width/height | 几何 13/13 通过；E08 p95 **57.0ms**、max 89.3ms、24/3154 长帧，唯一失败为 p95 |
| 缩小写入后 | 全新 fixture，仅真实 60 秒 E08；移动时只写 transform，resize 时才写宽高 | E08 p95 **54.9ms**、max 90.6ms、20/3194 长帧，唯一失败为 p95 |

两次均在 Chromium 151.0.7922.71 / Ryzen 7 5800H / SwiftShader 上运行真实 8 窗口、双 PTY、万条目录和 16 MiB 传输；传输校验、队列和终端输出检查通过。两次均未达到 50ms 门槛，短时差异不足以证明稳定收益，因此**没有保留这项实现**。`WindowFrame.vue` 已恢复原来的 RAF 内响应式几何更新，随后 `npm run build` 退出0；浏览器 49/49 通过报告对应的正是恢复后的实现。测试夹具和 Playwright 已停止。

这项尝试不能覆盖当前源码一小时 E08 的 p95 51.7ms 失败。后续需要从终端批处理、xterm 渲染或窗口更新路径找出可重复的改善，再用无诊断器场景验证。
