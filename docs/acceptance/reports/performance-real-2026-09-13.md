# 真实混合负载性能验收（短时场景最终通过）

最终构建的本机短时场景通过：p95 **38.8 ms**，最大48.5ms，302帧无长帧；八窗口、两个实际PTY、万条目录和16MiB跨节点传输全程并行。长期内存、不同网络与大文件性能仍未完成，E08整项继续进行中。下文保留初始失败及修复证据。

## 实现与测量

`cmd/devfixture --performance` 在本次私有目录创建 10,000 个真实小文件、16 MiB 传输源和另一节点的空目标目录。`web/tests/real/performance.spec.ts` 使用真实 HTTPS Master、两个 Daemon、两个 PTY、八窗口、目录分页和跨节点后台传输，不拦截 API 或伪造输出。检查目录总数、最多 300 个 DOM 行、两个终端实际 WSS 数据以及目标校验结果。

通过实际鼠标拖动测量，从 pointermove 事件时间戳到两个 requestAnimationFrame 周期，包含事件排队和界面更新机会。这是保守的浏览器反馈代理，不是硬件光学测量。仍要求 p95 ≤ 50 ms，并检查采样结束时传输仍在运行。

## 发现与已修正项

- 前两轮测试分别因已进入详情页却仍等待列表入口、启动器带图标导致精确文本定位失败，已修正；没有可用性能结果。
- 初始512 MiB源试跑：353帧中346个长帧，heap113,421,216 B，RTT p95 456.5ms。旧探针只量事件处理后至同一rAF，所得2.8ms低估反馈，明确作废。传输未完成，试跑已中断。
- ReadChunk每块前后重新哈希整文件，512 MiB源数分钟只推进数MiB。版本校验保持，但大文件吞吐问题尚未优化；16 MiB复现规模不能证明大文件问题解决。
- RecoveryService改为合并数据库忙碌期间的重复快照，从Vue原始状态复制；保留同步日志。恢复测试9/9通过，包括突发更新以及快照完成期间新增修订，并从独立存储恢复最终正文。该优化不足以解决终端每事件完整屏幕序列化开销。
