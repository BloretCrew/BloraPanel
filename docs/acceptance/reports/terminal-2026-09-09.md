# B05 终端库与原始输出归档验证

日期：2026-09-09。范围：`internal/terminal/**`，F06、A06/A08/A09/A10/A17 的后端子场景。本文不将独立库验证记为浏览器或全产品验收通过。

## 已实现

- Linux 使用锁定的 `github.com/creack/pty v1.1.24` 创建真实 PTY、控制会话与初始尺寸，原始字节读取、限时输入、尺寸修改和显式关闭。交互 shell 的前台作业可拥有独立进程组；关闭时通过 PTY 查找前台组、确认 session 归属后结束该作业。宿主原生模式需要显式 `AllowNative`，属于可信管理员能力，不作为不可信租户隔离。
- Windows 使用 `golang.org/x/sys v0.40.0` 的真实 ConPTY 与 Job Object：原子 Job 归属、挂起创建、确认归属后恢复线程、禁止 breakaway、关闭时终止 Job 并核对 ActiveProcesses；关闭 ConPTY 时保持输出消费。能力不足返回错误，没有成功桩或不受控降级。
- 会话独立于创建请求 context、浏览器视图及窗口。Detach 释放视图与对应租约，不结束 PTY。可列出、重新挂载、显式关闭、删除已结束会话。会话记录与归档持久化；Daemon 重启时无法重新挂载的会话标为 `invalid`，保留原身份和输出，不启动替代 shell。此时显式关闭不能伪造退出确认。
- 一份输入/尺寸租约绑定 userId 和 viewId，支持到期、同持有人续租、显式接管；原持有人立即失去输入权。只读观察、每次资源授权、用户隔离、所有视图撤销、持久化撤销记录和显式恢复授权均有接口。
- 原始输出和 resize 采用带 CRC 的有序记录。输入完全不入归档。归档按段轮转，有界磁盘、消息与订阅数量；没有随慢浏览器增长的输出队列。尾部不完整记录可截断恢复，完整记录损坏明确拒绝读取。
- 归档写入失败会显示诊断并结束受影响 PTY，关闭期间继续消费输出。后端不能确认关闭时状态为 `invalid`，关闭操作返回错误。

代码入口：[manager.go](../../../internal/terminal/manager.go)、[archive.go](../../../internal/terminal/archive.go)、[Linux PTY](../../../internal/terminal/native_linux.go)、[Windows ConPTY](../../../internal/terminal/native_windows.go)。

## 集成合同

`New(Options)` 接受 Root、MaxSessions、MaxAttachments、Archive、AllowNative、Backends 和 Authorize。单个根目录必须只由一个 Manager 拥有。默认保留 64 个会话，每会话最多 16 个视图、16 MiB 原始归档、1 MiB 分段；预算随 Session 元数据返回。已结束会话仍占保留配额，显式 DeleteSession 可释放。没有隐藏的空闲结束策略。

`Create(ctx, CreateRequest)` 使用 OwnerID、`model.ResourceRef`、可选 RunID、Backend、命令参数数组、Directory、Environment、Cols/Rows。创建时持久化 intent；不把命令或环境写入会话元数据。

`Attach/Read(ctx, sessionID, userID, viewID, after, maxBytes)` 返回 `Batch{Events, Earliest, Latest, Next, Gap}`。每条事件为 `Event{Sequence, Kind, Data, Cols, Rows}`：

- after 是已解析完成的最后一个**事件号**，首次为 0；输出与 resize 都递增。Next 是本批最后事件号，Latest 是读取时最新可用事件号，Earliest 是最早保留事件号。空归档边界为 Earliest=1、Latest=0。
- 与 Protobuf DATA 的**字节序号和 CREDIT** 分开；不能将事件号填成消费者处理字节数。默认读取预算 64 KiB，最大 1 MiB；最小为 32 KiB+32 字节，尺寸事件头同样计费。
- `Data` 是原始 `[]byte`，经 JSON 编码时为 base64；不能逐条按 UTF-8 字符串解码而破坏跨记录字符或 ANSI 字节。前端应交给 xterm 的字节输入接口。
- Gap 表示 checkpoint 所需的下一个事件已轮转删除，不能将缺口后的输出无提示地接到原屏幕。客户端必须明确显示缺口；提前于服务器的游标返回 ErrCursor。
- 客户端在 xterm 解析结束后提交屏幕、尺寸与事件号检查点。恢复屏幕、回放有序事件期间禁用任何自动终端响应；追到 Latest 后才开启实时输入。

`AcquireLease` 默认 30 秒，最大 2 分钟，客户端需显式续租。`WriteInput` 最大一帧 32 KiB；`Resize` 同样要求当前租约。`Revoke` 由可信权限网关调用，清除指定用户全部视图与租约，并阻止旧挂载重试；`RestoreAccess` 用于之后明确恢复授权。

Authorize 回调按 `terminal.read`、`terminal.input` 和创建 native 时的 `host.manage` 实时判断资源权限；nil 默认只允许 owner。Master/Daemon 入口必须先把已认证主体与资源绑定，并独立要求 `host.manage` 才能创建 native 终端。普通用户隔离终端通过显式注册的 `Backend.Spawn(ctx, SpawnSpec) (Process, error)` 接入；未知 backend 不回退到 native。Process 的 Write/Close 必须有期限，Close 只能结束该 shell/exec，不能关闭其所在的独立实例或容器。

通用 `OpenArchive(root, ArchiveOptions)`、AppendOutput、AppendResize、Read、Bounds、Bytes、Close 也可供实例追加日志使用。归档只负责输出保留；网络消费额度与优先级由协议层处理。

## 已运行证据

环境：Linux amd64，项目现有 Go 1.25.9、PTY 与 `/bin/sh`。本轮无需修改主机配置，也未请求网络/socket 权限。所有进程与目录均为测试创建并由测试结束清理。

```sh
GOCACHE=/tmp/blora-go-build GOMODCACHE=/tmp/blora-go-mod GOPATH=/tmp/blora-go GOFLAGS=-buildvcs=false go test -race -v ./internal/terminal
```

退出码 0，12 个测试通过，最后一次完整输出：`ok blora.dev/panel/internal/terminal 1.185s`。

| 场景 | 实际结果 |
| --- | --- |
| UTF-8 字节分片、中文、ANSI、NUL、非 UTF-8 字节、resize 顺序 | 原始字节保真，独占游标及重开归档回放通过 |
| 分段轮转、磁盘预算、旧 checkpoint 缺口 | 磁盘总字节未超设置上限，Gap 与边界明确，轮转重开后事件号继续递增 |
| 部分写尾部与完整记录损坏 | 不完整尾部恢复，CRC 不一致拒绝 |
| 大块输出与高频 resize | 分块、消息与元数据预算生效 |
| 多人观察、独占写入、接管、租约到期、Detach | 只读无法写入，旧租约不能继续使用，关视图不终止会话 |
| 身份、数量与 native 默认门禁 | 他人会话不可见，订阅/会话超限拒绝，native 默认禁用 |
| Daemon 记录恢复 | 原 ID 保留、状态 invalid、无替代进程、旧租约不能写入 |
| 权限撤销与归档故障 | 撤销持久化，旧流/旧挂载拒绝，输出故障有诊断并清理 PTY |
| 后端无法确认退出 | 返回错误且状态 invalid，未显示成功 |
| 真实 PTY、中文 ANSI、132×42 尺寸、原会话重挂 | 取消创建 context 后仍活跃，stty 返回 42 132，命令未重复执行 |
| 2 MiB 输出，全程无浏览器订阅 | 顺利结束；64 KiB 配额下实留 56825 字节，Earliest=477、Latest=490、Gap=true（事件划分随 OS 读取分片变化） |
| 真实交互 shell 前台 sleep 独立组 | 通过 PTY 识别前台组，显式关闭后 pidfd 确认该测试进程已退出 |

```sh
GOCACHE=/tmp/blora-go-build GOMODCACHE=/tmp/blora-go-mod GOPATH=/tmp/blora-go GOFLAGS=-buildvcs=false go vet ./internal/terminal
GOCACHE=/tmp/blora-go-build GOMODCACHE=/tmp/blora-go-mod GOPATH=/tmp/blora-go GOFLAGS=-buildvcs=false GOOS=windows GOARCH=amd64 go test -c -o /tmp/blora-terminal-windows.test.exe ./internal/terminal
GOCACHE=/tmp/blora-go-build GOMODCACHE=/tmp/blora-go-mod GOPATH=/tmp/blora-go GOFLAGS=-buildvcs=false GOOS=windows GOARCH=amd64 go vet ./internal/terminal
```

三条命令退出码均为 0。Windows 测试产物位于 `/tmp/blora-terminal-windows.test.exe`，包含真实 ConPTY 中文输入/输出、resize 与 Job 关闭测试。

## 未验证与集成待办

- Windows 真机环境未提供。交叉编译与 vet 通过不计为 ConPTY/Job 真机通过；在获准 Windows 主机运行 `go test -v ./internal/terminal -run TestWindowsConPTY`。
- Docker exec 由主代理通过 Backend 接入；本独立库的 backend 替身测试不作为 Docker 实际执行证据。
- Master/Daemon 网关、实时 WSS/CREDIT、前端 xterm 检查点、vim/top 刷新、浏览器标签移窗与两用户资源撤权的全链路由集成验收覆盖，本报告未将这些场景标为完成。
- 2 MiB 无订阅测试证明本库输出保留有界，不证明并行文件传输下的控制通道公平性或浏览器 p95 指标。
- Linux 原生 PTY 是管理员可信 shell；它使用控制终端、session/进程组归属，不宣称抵御主动 setsid 逃逸或提供容器级租户隔离。普通用户不得使用这一后端。

API 依据：锁定依赖本地源码，以及微软官方的[ConPTY 会话创建](https://learn.microsoft.com/en-us/windows/console/creating-a-pseudoconsole-session)、[ConPTY 关闭](https://learn.microsoft.com/en-us/windows/console/closepseudoconsole)和[Job Objects](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects)文档。ConPTY 属性传入的是 HPCON 值本身；输出消费必须与关闭过程并行。
