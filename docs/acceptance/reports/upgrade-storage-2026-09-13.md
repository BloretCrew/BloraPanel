# 数据库升级版本保护与运维文档

核对升级流程发现，旧启动逻辑只逐个检查自身已知迁移，未拒绝数据库中更晚或不连续的版本记录。当前启动先要求已有记录构成内置迁移列表的连续前缀，再事务执行剩余迁移；未知版本、记录缺口或不可读版本拒绝启动，不能静默接入不兼容数据库。

`go test -race ./internal/storage -count=1`：完整模块通过，17.216s。新增真实SQLite测试分别覆盖未来版本、缺失中间记录、业务数据和版本记录不被改写，以及从已知旧版本应用剩余迁移。

新增[运行、升级与恢复手册](../../operations/OPERATIONS.md)，对应当前实际命令行、健康检查、私有身份目录、停机一致性备份、升级/回退和故障诊断。说明Master健康与节点/实例健康的区别、PTY和独立运行的真实重启边界，以及Windows控制台程序不能直接当作原生SCM服务安装。

没有执行公开部署、生产回退或系统服务安装。文档流程不能替代Windows、物理掉电或跨节点一致恢复的实际演练。最终构建检查结果见PROGRESS最新记录。
