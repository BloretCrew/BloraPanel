# 扩展生命周期与视图迁移增量

注册表公共操作现在使用同一个读写锁；包读取使用同一次验证的清单/包体快照。升级和禁用写入期间，读者不会看到两个版本混合的文件。回滚在任何覆盖前验证旧清单身份、摘要、签名、包结构及依赖；损坏的回滚快照不会覆盖当前可用包。回滚保持当前禁用状态。启用与能力调用检查依赖是否启用、版本是否匹配。数据清理入口验证应用 ID。

AppHost 注册表改为响应式；重新加载扩展会更新清单、能力与组件，不复用旧版本闭包。拒绝请求/响应应用身份不一致和保留应用 ID。前端模块可以导出 SDK `StateMigration` 类型的 `migrate(previous,targetVersion)`；迁移在 opaque iframe 中、start 之前运行，10 秒超时。宿主检查旧现场和资源绑定仍匹配、目标版本和状态结构正确，再将状态及版本一次提交。缺少迁移、抛错或冲突时显示错误并保留旧现场。刷新恢复不会预先把旧状态版本改号。

验证命令与范围：

```sh
GOMODCACHE=/tmp/blora-go-mod GOPATH=/tmp/blora-go GOCACHE=/tmp/blora-go-grant-idem go test -race ./internal/extensions -run 'TestLifecycle|TestCorruptRollback|TestConcurrentLifecycle|TestRollbackKeeps|TestBundleIntegrity' -count=1
```

退出 0（1.094s）。包括损坏包体/元数据/身份的回滚保持当前包、并发升级和读者一致快照、禁用依赖与回滚状态。最终真实 TLS 扩展安装/后台执行定向测试通过（10.771s）。

浏览器新增迁移 1→2、升级迁移抛错、退回兼容版本后正文不重复迁移场景；扩展浏览器套件 4/4 通过（20.1s，后端路由替身）。注册表单元测试发现旧迁移闭包残留，已修正后全前端单元 30/30、类型检查、SDK 构建、前端生产构建与 `make check` 通过。资源绑定也纳入迁移旧现场条件检查；最终迁移定向 1/1 通过（6.9s），前端构建退出 0。无活动测试服务；本轮没有重跑完整 Go race，采用上述针对性证据。
