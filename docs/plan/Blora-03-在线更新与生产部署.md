# 核心在线更新与生产目录

更新：2026-10-09。本文记录用户批准后逐次澄清的最终合同；实现与验证状态见 [PROGRESS](../execution/PROGRESS.md)，运行方式见 [README](../../README.zh-CN.md)。

## 1. 最终目标

更新 Master 或 Daemon 时，不停止运行中的托管实例。管理服务可以短暂重启、断线重连；交互终端会话不保证连续，浏览器上传可能需要续传。无法核对实例归属、持久化任务结局或独立日志/输入助手时，拒绝切换，保留当前运行版本。

用户先提出更新包与分发目录，随后明确“Git 那套逻辑”，最终明确采用**已构建好的最新 Release**。因此更新机不拉源码、不运行编译、不依赖 Git、Go 或 Node。版本比较、固定目标、私有暂存、就绪后切换、失败保留旧版是这里的“Git 逻辑”，不宣称提供 Git 对二进制文件的网络增量传输。

原提案的自建签名索引、跨版本补丁依赖图、Go 插件热装载、稳定宿主与业务模块完全分离不再属于本轮合同。使用完整 Release 包，兼容时直接升到所选通道的最新版本；数据库或协议变化不安全时明确要求维护更新，不自行执行迁移链或降级数据库。

## 2. 更新来源与兼容性

- 默认项目：`https://github.com/BloretCrew/BloraPanel`。
- 默认通道：`beta`，允许预发布；`stable` 只允许正式 Release，排除草稿。
- 可选 `updates.apiUrl`：提供 GitHub 兼容 HTTPS API 的镜像入口。必须提供 Release、资源下载、标签/提交等对应接口；普通目录不是兼容 API。
- 所选 Release 的标签解析为确定的源码提交，不能将可移动分支当版本身份。
- Release 提供四个平台/组件归档、`SHA256SUMS` 和 `CORE-UPDATE.json`。每个归档另有逐文件 `MANIFEST.json`。
- 校验下载摘要、包内文件摘要、版本/组件/平台/提交、路径和文件类型。拒绝越界、链接、重复路径及超限包。校验后运行二进制的只读兼容信息入口，再核对管理重启能力、协议及数据库迁移指纹。
- Master 更新前核对全部未吊销节点（含离线节点）的协议；Daemon 核对当前 Master。下载完成、实际切换前再次检查发起账号的管理员身份，权限撤销会阻止切换。

HTTPS Release 来源是可信代码供应方；修改镜像/项目意味着选择另一可信供应方。摘要用于传输和载荷完整性，不冒充独立发布者签名。旧 `v0.1.0-beta.1` 不具备上述新元数据和更新入口，不能被当成支持在线更新的目标包；首次部署新启动器仍需一次人工安装。

## 3. 启动与切换

无参数命令不变：`./blora-master`、`./blora-daemon`；Windows 对应 `.exe`。同目录配置、身份、数据库、实例数据不被发行包覆盖。

一个稳定启动器持有状态目录的排他锁，并运行一个管理子进程。后台更新按固定目标下载完整预构建归档到私有暂存目录，验证后形成独立版本目录，再记录待激活版本。原管理子进程正常退出后，启动器才启动候选版本，始终避免两个管理进程同时写数据库。

Master 的就绪包括配置、数据库和监听建立；Daemon 的就绪包括配置、状态恢复和连接 Master。启动器持久化当前版本后才报告成功。候选无法启动或未在期限内就绪，启动器保留之前版本并记录失败。此回退只支持相同迁移指纹的维护版本；不会把旧二进制套到不兼容数据库上。

Daemon 在交接前暂停接收新任务，等待已有操作结束，不取消操作来强行更新。运行实例按 PID 出生身份、进程组/cgroup、Windows Job keeper 或 Docker 运行身份核对。原生实例独立日志/输入助手保持存活，新的 Daemon 重新挂载原运行。Master 重连不能通过旧连接 context 取消已接受的实例操作。

更新只替换管理子进程，不通过 `systemctl restart` 结束整个服务组，也不对实例发送停止或重启。外部服务包装器必须保留独立运行助手；不能把整个进程树绑定到管理子进程退出即杀死的策略。

## 4. 网页入口与状态

系统管理员在设置更新 Master；在节点管理中单独检查/更新 Daemon。状态包括当前组件、平台、版本、固定提交、来源、检查结果、兼容原因，以及下载/校验/交接/成功/失败阶段。

检查与下载在后台执行，短请求返回后可轮询；不让长下载占住管理 RPC 超时预算。应用请求有持久化幂等回执，重复提交不重复切换；重连后展示真实持久化结果。普通用户、第三方应用及仅有 `host.manage` 的账号不能更新核心。

在线更新适用于程序与协议/存储兼容的维护版本。稳定启动器自身的重大变更、数据库架构迁移和不兼容协议更新需要维护流程。网页必须展示阻止原因，不把“下载完成”当成“已更新”。

## 5. 生产目录

用户已于 2026-10-09 将开发工作树移到 `/data/projects/blora-panel`，原路径 `/data/instances/blora-panel` 预留生产安装。开发与生产仍分离：生产身份、数据库和实例工作目录不混入开发 Git checkout。路径选择按用户要求，以下为目标布局示例，本任务仅给部署指导，不执行安装。

生产安装示例（本任务不创建或部署）：

```text
/data/instances/blora-panel/
  master/
    blora-master
    master.json
    web/dist/
    state/master/
      master.db
      extensions/
      updates/
        revisions/<固定提交>/
        active.json
        job.json
  daemon/
    blora-daemon
    daemon.json
    state/daemon/
      身份与数据库
      实例独立输入/日志助手记录
      updates/
```

可使用其他数据绝对路径。相对配置路径始终按**原安装目录**解析，不能因为激活了新版本而移到版本缓存内。Master 默认自带的 `web/dist` 随同 Master 更新；显式配置的独立前端路径仍由管理员更新。Node/npm 是开发工具，不是生产前端服务。

## 6. 验证边界

需要验证：真实实例跨 Daemon 重建存活与输入/日志恢复、启动器候选失败回退、身份与状态保留、管理员撤销、协议/迁移变化拒绝、归档篡改和路径攻击、重复请求及断线后的回执、前端构建与两个目标平台构建。

Windows 编译不是新增 Windows 真机 PASS。已发行 beta、现有生产节点或用户自己的环境不会在本任务中自动更新。具体已通过结果及尚未覆盖环境以验收报告为准。
